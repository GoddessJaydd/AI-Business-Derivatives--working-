## 4. Learned skills and workflows

Each entry can be saved as a skill.

### Skill: starnest-context-navigator
**Description:** Navigate a very large handoff or master-context file without reading all of it. Use when a project file is thousands of lines long and you only need one section.
**Instructions:**
1. Read the first ~775 lines (overview, priorities, plan, guardrails, open questions).
2. Grep for headings (`^### 1[1-4]\.|^## 1[2-4]\.`) to get line numbers for each section.
3. Read only the section you need with offset/limit (e.g. venture 17 was lines 2440 to 2509).
4. Tell the user which parts you did not read.

### Skill: small-batch-prospect-research
**Description:** Build a prospect list from public websites without bulk scraping, respecting the shared API rules. Use before any outreach list is created.
**Instructions:**
1. Confirm the buyer niche and geography.
2. Run a web search per niche (e.g. "small CPA bookkeeping firm Oakland California team contact", "independent insurance agency Mariposa California contact email").
3. Fetch each business's own website with a prompt asking for: firm name, city, services, size, public email, phone, address, and one personalizing detail.
4. If a site returns ROBOTS_DISALLOWED or a 403, skip it. Do not work around it with curl, Python or archives.
5. Record only what the page says; mark unknown fields as "none public". Do not guess emails.
6. Prefer businesses with a public email; list phone/form-only businesses separately with a call script.
7. Flag lower-fit prospects (franchises, national-insurer agents, large firms).
8. Record the source and date (Oct 4, 2026) in the sales log.

### Skill: tailored-cold-email-draft
**Description:** Write one short personalized outreach email per business from facts on their own website. Use for AI training outreach (or any service outreach) that the founder will send personally.
**Instructions:**
1. Subject: plain and specific to the business type (e.g. "Saving time on owner and tenant communication").
2. Opening line: one verifiable detail from their site (e.g. "more than 850 rentals", "serving the Bay Area since 1911", "four CPAs"). Do not invent flattering claims.
3. Middle: what the workshop does (90 minutes, their own sample tasks, reusable templates, rules for confidential data, human review before sending).
4. Close: one low-pressure ask (15-minute call or a one-page outline).
5. Signature: sender name, [BUSINESS NAME] | [ADDRESS].
6. Opt-out line: `Reply "no thanks" and I won't contact you again.`
7. Tone adjustments: law firms get a safe-use emphasis and an acknowledgement of firm policy; franchise/national-insurer agents get a note that corporate rules may apply.
8. Verify every claim against the fetched page before delivering. Never send; the founder reviews and sends.

### Skill: outreach-sales-log
**Description:** Track a seven-day outreach sprint. Use when the master context calls for a dated sales record.
**Instructions:** Create a CSV with the columns in section 5, one row per prospect, source and date filled in, other columns blank until an event happens. Log new prospects and follow-ups separately, and count both. Review at 50 touches (minimum) and 100 touches (weekly target).

### Skill: ai-training-workshop-delivery
**Description:** Deliver the 90-minute "AI Workday Tune-Up" workshop. Use once a client says yes.
**Instructions:**
1. Pre-call (15 min): ask the three tasks that take the most time, tools in use, anyone already using AI; collect 2 to 3 non-confidential sample tasks 48 hours ahead.
2. Agenda: 0:00 to 0:10 what AI is good and bad at; 0:10 to 0:25 the 4-part prompt (role, task, context, format); 0:25 to 0:55 hands-on with their tasks; 0:55 to 1:10 safe-use rules; 1:10 to 1:20 build 3 to 5 reusable templates; 1:20 to 1:30 Q&A and audit offer.
3. Deliver within 24 hours: one-page "how we use AI here" guide, 3 to 5 prompt templates, 7-day follow-up email.
4. Log delivery hours and cash collected. Ask (do not assume) for a testimonial or referral.

### Skill: ai-workflow-audit
**Description:** Follow-on audit after a workshop shows a clear need.
**Instructions:** Interview (typical week, repeated tasks, stalled handoffs, longest writing/research tasks, recurring mistakes, confidential data). Deliver one table: current state, pain point, possible AI use case, estimated impact (labeled as an estimate), complexity, priority. No guaranteed savings. Recommend implementation only for validated, low-risk cases.

### Skill: seven-day-ai-training-sprint
**Description:** Run the recorded seven-day lock-in plan for the cash offer.
**Instructions:** Day 1: five warm leads plus ten qualified prospects (15 touches), one-page offer, payment path. Day 2: ten new prospects plus Day-1 follow-ups, two tailored samples or mini-audits (about 20 touches). Day 3: ten new prospects and ten follow-ups, tighten offer from objections, aim for two positive replies or one call. Day 4: ask directly for a paid next step, delivery checklist. Day 5: continue ten new prospects, deliver first sale, seek testimonial/referral. Day 6: follow up warm leads, build a reusable delivery SOP, optionally batch three posts. Day 7: follow-ups, ten new prospects, review at least 50 qualified touches, decide continue or revise.

### Skill: local-folder-delivery-via-device-bridge
**Description:** Save finished files to the user's connected folder. Use when the user wants files saved locally.
**Instructions:**
1. List the destination with `device_list_dir` first; note sizes and `mtimeMs` of existing files.
2. Write finished files under `/mnt/user-data/outputs/`.
3. Commit with `device_commit_files` using `stagedPath` and `devicePath`. For files that already exist (here, empty placeholders), pass `expectedMtimeMs` from the listing so a newer user edit is never overwritten. New files need no guard.
4. Report folder and file names in plain language. If a commit is rejected, say which file stayed in the conversation and why.
5. Gotcha: the original folder name ends with a trailing space ("AI Business Derivatives "); lookups with or without it failed until the user connected the `17-ai-training` folder.

### Skill: evidence-first-handoff-reporting
**Description:** Report status without inflating it. Use when summarizing StarNest progress.
**Instructions:** Separate source claims, observed evidence, assumptions and estimates. Targets and scorecards are not results. A folder, instruction file or planning row is not a finished business system. Say plainly what was not read or not verified.
